# 포트폴리오 개편 방향 제안 (2026-09-01)

## 결론

콘텐츠를 현재 상태(agent_harness 중심)로 갱신하고, 구조적 버그를 함께 고친다.
스택은 vanilla HTML/CSS/JS를 그대로 유지하고 빌드 도구 도입은 이번 범위에서 제외한다.

---

## 배경 — 현재 상태

- `index.html` 하나에 전역 함수 기반 수제 DSL(`CreateXXX` / `AddXXX`)로 섹션을 조립하는 구조이며 빌드 도구는 없다.
- 구성: 메인 인트로 → About Me(인적사항) → Skill → Archiving(외부 저장소 링크) → Projects(WOT 모작, Unreal 액션게임, 포트폴리오 웹페이지, OpenCV 차량찾기).
- 마지막 작성 시점은 2024년 5월이며, 이후 진행한 agent_harness / platform / graphics / World-of-Tank-imitation-Refactoring 작업이 전혀 반영되어 있지 않다.
- 이 포트폴리오는 현재 취업/이직 준비(신입 개발자) 목적으로 쓰인다.

## 발견된 문제

1. **중복 렌더링 버그**: 프로젝트 설명 4종 세트(`Tank 설명` / `Tank 설명2` 등)와 `CreateSliceBox` + `AddProjectContent` 호출이 그대로 두 번 반복되어 있다. 실제로 같은 프로젝트 카드가 두 벌 렌더링될 가능성이 높다.
2. **반응형 미흡**: 1000px 이하에서는 메뉴 항목이 대체 UI 없이 그냥 사라진다(햄버거 메뉴 등 대안 없음).
3. **개인정보 노출**: 생년월일, 상세 주소지(구/동 단위), 휴대폰 번호가 그대로 공개되어 있다. 공개 배포되는 정적 페이지 특성상 노출 범위를 재검토할 필요가 있다.
4. **콘텐츠 노후화**: Skill의 "공부중인 항목"이 2024년 Unity/C#에서 멈춰 있고, 최근 진행한 AI 협업 개발(agent_harness) 관련 역량이 전혀 드러나지 않는다.

## agent_harness 요약 (신규 대표 프로젝트 후보)

- Claude Code 기반 AI 협업 개발을 위한 **재사용 가능한 Task Delegation 워크플로우 프레임워크**.
- Task → Brainstorming → Strategy → Implementation → Commit Report로 이어지는 작업 위임 절차를 정의한다.
- `platform → graphics → projects` 방향의 멀티 레포 의존 구조를 git submodule로 연동하고, 각 레포는 `agent_harness/CLAUDE.md`를 import해 공통 규칙을 공유한다.
- SOLID 원칙, 외부 라이브러리 래핑, 기능별 유닛 테스트 작성 등 개발 원칙을 문서로 강제한다.
- 2026-09-01 기준 본 저장소(`kjejhk37.github.io`)에 git submodule로 추가 완료(스테이징 상태, 커밋/푸시는 아직 진행하지 않음).

이 프로젝트는 "AI 도구를 활용한 협업 프로세스를 직접 설계·운영한 경험"을 보여줄 수 있어, 신입 개발자 포트폴리오에서 다른 지원자와의 차별점이 될 수 있다.

## 제안 방향 (권장안)

### 1. 신규 대표 프로젝트로 agent_harness 추가
- "AI 협업 개발 워크플로우 프레임워크"로 소개.
- Task Delegation 프로세스 설계, 멀티 레포 서브모듈 체인 조율, 문서 기반 협업 규칙 정립 경험을 강조.
- 기존 WOT 모작 / Unreal 액션게임 / 포트폴리오 웹페이지 / OpenCV 차량찾기 프로젝트는 유지하되, 최신 작업인 agent_harness를 상단(또는 최신 항목)으로 배치.

### 2. 구조적 버그 수정
- 프로젝트 설명 4종 세트가 통째로 중복 렌더링되는 부분(`...2`로 끝나는 블록 및 두 번째 `CreateSliceBox`/`AddProjectContent` 호출)을 제거.
- 반복되는 프로젝트 카드 마크업을 데이터 배열 + 루프 방식으로 바꿔, 같은 종류의 중복이 다시 발생하지 않도록 구조를 개선.

### 3. Skill 섹션 갱신
- "공부중인 항목"을 2024년 Unity/C#에서 최근 작업(agent_harness, 멀티 레포/에이전트 오케스트레이션 등)으로 갱신.

### 4. 개인정보 노출 축소
- 생년월일 · 상세 주소지 · 휴대폰 번호 노출을 줄이고, 이메일 · GitHub 링크 등 연락 가능한 채널 위주로 재구성.

### 5. 스택 유지
- vanilla HTML/CSS/JS, GitHub Pages 정적 배포 구조를 그대로 유지한다. 빌드 도구 도입은 이번 범위에 포함하지 않는다.
